# Saliency-Based Data Cleaning (Self-Supervised Saliency Auditing)

## The Concept
Traditional data cleaning focuses on outliers in the feature space or label noise in the target space. **Saliency-Based Data Cleaning** introduces a third dimension: **the explanation space**.

By auditing the *saliency maps* (explanations) generated by a model, we can identify data points where the model's reasoning is anomalous. If a model is forced to justify an incorrect label (noise) or a spurious correlation (shortcut), its saliency map will often differ significantly from the "typical" reasoning pattern for that class.

## Why it works
A model trained on clean data should focus on the core features (the "signal"). In the presence of noise:
1.  **Label Noise:** The model tries to justify an incorrect label (e.g., "3" for an image of an "8"). The saliency map becomes diffuse or focuses on irrelevant background features.
2.  **Shortcuts:** The model finds a "cheat" (e.g., a watermarked pixel) and focuses entirely on it instead of the actual object.

## The Workflow
1.  **Initial Training:** Train a model on the noisy/uncleaned dataset.
2.  **Saliency Generation:** Generate saliency maps (masks) for each training example using `saliencytools`.
3.  **Prototype Computation:** Compute a "typical" saliency map for each class (the prototype).
4.  **Auditing:** Use `saliencytools.maskcompare` metrics (like `cosine_distance` or `emd`) to measure the distance between each sample's mask and its class prototype.
5.  **Filtering:** Flag samples with high distances as "suspicious" for manual review or automatic removal.

## Implementation with `saliencytools`
```python
from saliencytools.maskcompare import cosine_distance

# Calculate distance of a sample mask to its class prototype
suspicion_score = cosine_distance(sample_mask, class_prototype_mask)

# High suspicion_score indicates potential noise
if suspicion_score > threshold:
    flag_for_cleaning(sample)
```
